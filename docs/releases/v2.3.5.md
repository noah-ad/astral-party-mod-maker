# v2.3.5

本地完整视频版，尚未发布到 GitHub Releases。

## 动态资源定位

- 旧逻辑按资源包大小、修改时间查找程序集，还只接受 Unity 2021 资源。在多个游戏版本缓存共存时，可能写入旧包：文件哈希校验正常，游戏却不会加载它。
- 从当前游戏的 `settings.json` 读取 catalog 版本，按 `AstralParty.Runtime.dll` 的主依赖、缓存名称和内容哈希精确定位 `__data`。不再依赖修改时间或旧 Unity 版本限制。
- 当前版本的 catalog 或程序集未下载时停止操作，不回退到旧包。绕过界面的直接写入 API 也会在生成前、写入前重复检查目标。
- 区分“文件已写入”和“当前版本绑定已校验”。旧版本记录、暂停标记、缺失文件不会继续显示有效动态预览；旧替换包也不能被当作当前版本导出。
- 旧绑定指向不同版本时，应先在工具中还原旧动态，再重新替换。不会自动把旧 DLL 覆盖到新版本，也不删除其他缓存。

## 离线视频组件

- 完整视频版的 `data/Tools/video` 包含 FFmpeg、Python、CriCodecs 和封装 / 检查脚本，不需要其他用户重新下载或安装。
- “检查组件”仅验证随包程序，不触发下载。精简标准版仍保留下载入口。
- 打包脚本默认生成完整视频版；`-WithoutVideoRuntime` 才生成精简标准版。缺少组件或声明时构建失败，不会输出名不副实的完整包。
- 保留 Python 许可证、CriCodecs 元数据、FFmpeg 的许可证和原始构建说明。公开分发的条款限制见 `data/Tools/video/DEPENDENCIES.md`；本地打包不等于完成公开再分发授权。

## 范围

保留 v2.3.3 的直接覆盖 ZIP 混合来源导出、v2.3.4 的旧 Mod 记录修复。本次不改变卡牌或立绘补丁的显示算法，不借用官方异画，不改游戏启动、联网和系统代理。测试使用资源副本，不写入实际游戏。

文件写入、版本绑定、容器解码和本地预览均不能替代真实游戏内播放验证。独立动态方案仍为实验功能；若本机当前版本的资源尚未下载，工具会明确提示，不能靠补丁修复资源下载失败。

## 验证

- 497 项回归检查、100% 至 250% 的模拟 DPI 布局检查通过。
- 真实程序集资源副本验证了新旧缓存共存下的精确选择、手牌与立绘同时安装、仅导出当前版本包及逐字节还原，源游戏资源未改动。
- 完整视频包在空用户组件缓存下完成 FFmpeg / Python 启动、去绿幕裁切预览、MP4 到 USM 转换及透明度 / 帧数检查，没有下载或用户组件安装。
- 完整包移动到中文和空格路径后可启动，组件仍可导入；包内 .NET 运行时、版本、图标和 EXE + data 结构检查通过。
