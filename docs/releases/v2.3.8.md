# v2.3.8

本地完整视频版，尚未发布到 GitHub Releases。

## 安卓贴图重建

- 作品页与工具页新增“导出安卓贴图 / 安装并校验”。普通安卓缓存贴图的 ZIP 导出也进入这个流程，避免只复制旧哈希目录。
- 从连接的手机读取当前 APK、游戏版本和 catalog，按贴图名定位当前安卓原始包。不会把 PC Bundle 写到手机，也不会重命名旧 Bundle 冒充新版本。
- APK 内置贴图使用独立 `JixModResources/<包编号>/*.bundle`，只修改选中贴图包在当前 catalog 中的路径与 CRC / 大小选项。保留其它资源表字段、依赖、对象、类型树和流式文件。不修改 APK、DLL、登录资源、代理或系统权限。
- 图片按当前安卓贴图尺寸等比适配，不拉伸；写回后核验目标像素、安卓平台、类型布局及非目标对象。Bundle 使用 LZ4 无损压缩，减少文件体积；纹理仍是 RGBA32，不能将包压缩等同于降低 GPU 内存。
- 支持从当前作品或 `.jxpack` 选择贴图，按名称搜索和勾选导出。不在当前资源表中的图片单独列出，不用旧包悄悄代替。
- 支持已安装后的再次替换。只导出新增所选贴图时，未选择的已有独立贴图保留为前置依赖，安装清单记录其哈希；缺少前置文件时拒绝安装，并明确标为增量包，不冒充可在干净手机上直接使用的完整包。

## 完整性与恢复

- ZIP 导出前检查 UnityFS 声明长度；导出后重新打开 ZIP，对所有条目核对大小与 SHA256。原路径 ZIP 遇到已知失效的手机缓存映射时阻止导出。
- 安卓 ZIP 仍是直接替换文件，解压目标为 `Android/data/com.feimo.astralparty/files/com.unity.addressables/`，包含当前版本的 catalog 和独立贴图目录，不是 `AssetBundles/` 内部。校验清单单独保存在 `ZIP文件名.install.json`，不混进直接替换 ZIP。
- 推荐在工具中用 USB“安装 ZIP 并校验”。安装前检查 APK 哈希、游戏版本、资源表现状和游戏是否关闭；先备份资源表，暂存并校验贴图，最后提交 catalog，再读回验证手机文件。
- 安装失败会尝试恢复原资源表，并保留恢复记录。还原会核对设备、版本和当前资源表哈希，拒绝把旧 catalog 覆盖到新版或其它工具改过的资源表。
- 手机备份默认位于 `%LOCALAPPDATA%\JixModMaker\mobile-backups`。还原仅撤销资源表引用，保留未再引用的独立文件，以免误删后续包可能仍依赖的资源。
- MT 的 `close failed: EPERM` 是手机写入端错误，无法通过调整 ZIP 保证消除。不能因为普通 Download 目录能解压，就视为 Android/data 写入成功；USB 安装逐项读回 SHA256，以识别写入截断。

## 缓存隔离与交付

- 手机资源目录、独立资源副本不再自动附加本机 PC 热更新缓存；资源归属分析也使用同样的隔离规则。升级索引指纹后保留增量复用，不清除旧 Mod 记录。
- 继承 v2.3.7 的安装目录缓存索引、同名普通 / SFW 资源显示和分来源导出。
- 完整视频便携包继续提供 FFmpeg、Python、CriCodecs，并加入 ADB 组件及其协议文件。顶层为标明 v2.3.8 的 EXE 和 `data`。
- 新增安卓窗口纳入 96 / 120 / 144 / 192 / 240 DPI 排版测试。

## 验证边界

包结构与像素回读、ZIP 回读、手机文件读回、游戏启动、游戏内卡面显示是不同的验证步骤。工具会分别报告，不会将文件哈希校验通过表述为已确认游戏内生效。独立动态视频的实验性限制保持不变。

本次本机验证：按当前游戏 3.3.0 重建 894 张 Mod 贴图，其中 301～306 共 48 张；895 个安装文件全部通过手机 SHA256 读回。用户已确认全量安装后替换成功。单项试包只改一种卡面不能代表列表、细卡等其它展示位置，验证以全量安装结果为准。测试同时证明 128 KB 测试文件被截断到 100 KB 后会被拒绝。
